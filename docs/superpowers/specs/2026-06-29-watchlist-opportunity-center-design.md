# 自选股机会中心设计规格

## 目标

在现有总览中增加“今日机会”区域，每日对自选股进行可解释的机会排序，帮助用户优先检查最值得行动或规避的股票。系统以策略信号为核心，结合趋势、风险、新闻和估值信息，不接交易接口，也不将新闻热度直接解释为买入理由。

## 产品范围

第一版包含：

- 港股和美股自选股的每日综合机会评分与排序。
- 最新开仓、加仓、平仓和风险退出信号置顶。
- 个股新闻为主、所属行业及宏观新闻为辅的新闻关联。
- 评分构成、变化原因、相关新闻、策略依据和风险提示。
- 港股与美股收盘后的自动刷新，以及用户手动刷新。
- 每日快照和新闻分析的本地持久化与历史回看。

第一版不包含：

- 自动下单或连接真实交易账户。
- 独立的全行业新闻门户。
- 盘中持续刷新或分钟级实时机会排名。
- 仅凭 AI 文本直接产生交易信号。

## 新闻数据流

新闻模块借鉴 `/Users/lianghuang/Desktop/investment-news` 的 RSS 来源目录、并发抓取、行业分类、每日摘要和原文引用方式。参考项目采用 MIT License；若复用来源定义或实质代码，项目中必须保留相应版权和许可说明。

新闻处理分为六步：

1. 从启用的 RSS/Atom 来源并发抓取文章，记录来源、发布时间、链接、标题和摘要。
2. 对规范化 URL、标题相似度和发布时间进行去重，避免同一事件被重复计分。
3. 根据股票代码、公司名称、常用别名、品牌和核心产品关键词关联自选股。
4. 将未直接命中个股但与其所属行业或关键宏观主题相关的新闻作为补充上下文。
5. AI 输出结构化分析：影响方向、影响强度、置信度、影响期限、摘要和理由，并保留原文链接。
6. 将原始文章、关联结果和分析结果保存到本地；同一文章在同一天不得重复总结。

新闻关联优先级为：个股直接相关新闻 > 所属行业新闻 > 宏观背景新闻。行业和宏观内容只能补充个股判断，不能单独把股票推为高机会等级。

## 综合机会评分

每只自选股每日生成 0 到 100 分的综合机会评分，默认权重如下：

| 维度 | 权重 | 主要输入 |
| --- | ---: | --- |
| 策略信号 | 40% | 最新动作、信号强度、历史样本外表现、信号新鲜度 |
| 趋势状态 | 20% | 中期趋势、价格动量、成交量确认 |
| 风险质量 | 20% | 波动率、最大亏损、回撤修复、下行风险 |
| 新闻影响 | 15% | 个股、行业和宏观新闻的方向、强度与可信度 |
| 估值状态 | 5% | 可获得的估值指标及其历史位置 |

各维度先标准化为 0 到 100 分，再按有效权重加权。某项数据不可用时，不把缺失视为负面；其权重按比例分配给其余有效维度，同时在页面显示数据缺失。策略信号维度必须始终是有效维度，否则股票只能标记为“数据不足”，不能进入“优先关注”。

### 风险闸门

综合分数之后还要应用风险闸门：

- 最新策略动作是平仓或风险退出时，机会等级最高只能为“暂不参与”。
- 出现高可信度重大利空或异常波动时，机会等级至少下调一级。
- 数据过期、价格序列不足或策略回测失效时，标记为“数据不足”。
- 新闻只能调整机会等级或解释原因，不能覆盖明确的策略退出信号。

最终等级为：

- `优先关注`：信号可执行、风险闸门通过且综合评分较高。
- `值得观察`：存在潜在机会，但信号、趋势或风险尚未充分确认。
- `暂不参与`：出现退出信号、风险闸门触发或综合评分偏低。
- `数据不足`：无法形成可靠评分。

评分阈值集中配置：第一版 `优先关注 >= 75`、`值得观察 >= 55`，其余为 `暂不参与`；上线前使用历史快照校验分布，避免大部分股票长期挤在同一等级。

## 每日快照与刷新

系统分别在港股和美股交易日收盘后生成对应市场的每日快照。快照只处理当前自选股，并复用已有价格、策略回测和走势预测缓存。

手动刷新执行增量更新：仅重新获取已过期或发生变化的数据。相同股票、市场日期、策略版本和评分版本对应同一个幂等快照；重复请求不得创建重复记录或重复调用 AI。

每个结果显示：

- 数据截至时间和市场日期。
- 自动刷新或手动刷新来源。
- 使用的策略版本与评分版本。
- 是否存在缓存、降级或数据缺失。

## 本地持久化

使用项目现有本地数据目录与数据库模式扩展机会中心，避免引入第二套互不兼容的存储体系。至少保存以下实体：

- 新闻来源及健康状态。
- 原始新闻文章与去重标识。
- 文章和股票、行业、宏观主题的关联。
- AI 新闻分析结果。
- 每只股票的每日评分明细、等级、解释和风险闸门结果。
- 每次自动或手动刷新任务的状态与错误。

历史默认永久保留，以支持查看单只股票的评分变化和验证评分是否具有后续解释力。后续如需清理，只增加显式的保留策略，不静默删除历史。

## 前端设计

总览顶部新增“今日机会”区域，位于自选股日常决策路径中，不新增独立新闻栏目。

默认视图：

- 按综合机会评分降序排列。
- 最近产生开仓、加仓、平仓或风险退出信号的股票优先显示，并给出信号日期。
- 每只股票最多显示一条最新策略动作，避免重复占据列表。
- 显示机会等级、综合分数、当日变化、最新动作、主要原因和数据截至时间。

交互：

- 点击股票跳转到该股票的走势预测和策略图表。
- 展开股票显示五项评分构成、相关新闻、风险提示与建议复核时间。
- 支持市场、信号类型和风险等级筛选。
- 提供手动刷新按钮，并显示任务进度、缓存命中和可读错误。
- 新闻条目必须显示来源、发布时间和原文链接。

页面文案必须明确说明：机会评分用于研究排序，不构成投资建议。

## 组件边界

- `news ingestion`：抓取、解析、来源健康和原始文章入库，不做股票判断。
- `news matching`：完成去重、股票别名匹配、行业和宏观关联。
- `news analysis`：把关联新闻转换为结构化影响信息，支持缓存与降级。
- `opportunity scoring`：只消费规范化输入，生成评分、等级、解释和风险闸门结果。
- `snapshot orchestration`：调度市场收盘任务、增量刷新、幂等和任务状态。
- `opportunity API/router`：提供当前列表、历史详情和刷新接口。
- `Today Opportunities UI`：只负责展示、筛选、跳转和刷新反馈。

这些模块通过明确的数据结构交互，使新闻来源、评分公式或界面能够独立调整。

## 错误处理与降级

- 单个 RSS 来源失败不阻断整个刷新任务；记录错误和连续失败次数。
- AI 不可用时保留原始相关新闻，并将新闻维度标记为不可用后重新分配权重。
- 新闻匹配置信度不足时不纳入评分，只作为“可能相关”展示。
- 价格或策略数据失败时，该股票标记为“数据不足”，不沿用旧信号冒充今日结果。
- API 始终返回结构化 JSON 错误，前端不得显示 `[object Object]` 或 HTML 响应正文。
- 页面保留上一次成功快照，同时明确标识其时间和本次刷新失败原因。

## API 契约方向

第一版需要提供以下能力，具体路径应遵循现有 router 命名规范：

- 获取当前自选股机会列表，支持市场、信号和等级筛选。
- 获取单只股票某日的评分明细、相关新闻和解释。
- 获取单只股票的历史评分变化。
- 创建手动刷新任务。
- 查询刷新任务状态。

列表响应应一次返回卡片所需字段；详情和新闻正文按需加载，避免总览首屏过重。

## 测试与验收

后端测试：

- RSS/Atom 解析、URL 与相似标题去重。
- 港股和美股代码、公司别名及行业关联。
- 个股、行业和宏观新闻的优先级及权重。
- 缺失数据时的权重重分配。
- 平仓、重大利空、异常波动和过期数据的风险闸门。
- 同一市场日期重复刷新时的幂等性与 AI 缓存。
- 来源失败、AI 失败、策略失败时的局部降级和 JSON 错误。

前端测试：

- 默认排序、信号置顶和每只股票仅显示最新动作。
- 筛选、展开、历史查看和股票页面跳转。
- 手动刷新进度、缓存提示、失败提示和旧快照时间。
- 数据不足与降级状态不会显示为正常高分机会。

手工验收：

1. 港股和美股各选至少三只股票，在对应市场收盘后生成快照。
2. 同一天重复刷新不重复新闻、AI 总结或评分记录。
3. 有近期策略动作的股票置顶，点击可跳到正确图表。
4. 单个 RSS 来源或 AI 服务断开时，其余评分仍可显示且降级原因清楚。
5. 查看任一股票连续多个交易日的评分历史和相关新闻原文。

## 成功标准

- 用户打开总览后能在一分钟内判断今天应优先研究哪些自选股以及原因。
- 每个高机会等级都能追溯到策略、趋势、风险和新闻输入。
- 每日重复刷新不会产生重复新闻或重复 AI 成本。
- 单项数据失败不会导致整个总览不可用或产生误导性行动建议。
- 保存的历史足以在后续版本评估机会评分与未来收益、风险之间的关系。
