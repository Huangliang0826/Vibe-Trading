# 今日机会质量校准设计

## 目标

为“今日机会”建立不偷看未来、可持续积累的结果验证体系，回答两件事：机会出现后是否赚钱，以及是否跑赢同期市场。校准只评价研究信号，不生成订单。

## 固定口径

- 每个每日机会快照都是一个待验证样本；同时标记其当日排名以及是否属于前三名。
- 信号在市场收盘后生成，因此入场价固定为信号日之后第一个交易日的开盘价。
- 5、20、60 日结果分别使用入场日起第 5、20、60 个交易日的收盘价。
- 港股基准为恒生指数 `^HSI`，美股基准为标普 500 `^GSPC`，基准采用相同入场日开盘和结算日收盘。
- 绝对收益为 `结算价 / 入场价 - 1`；超额收益为 `股票绝对收益 - 基准同期收益`。
- 胜率为绝对收益大于 0 的样本比例；跑赢率为超额收益大于 0 的样本比例。
- “最大亏损”为已成熟样本中最低的区间绝对收益，不称为最大回撤。
- 未到结算日、停牌、价格缺失或基准缺失的样本保持待验证/数据缺失状态，不使用更早价格替代。

## 架构

### 数据模型与持久化

新增 `OpportunityOutcome` 和 `OpportunityCalibrationSummary` 响应契约。SQLite 新增结果表，以市场、股票、快照日期、周期和计算版本为唯一键，保存当日排名、前三名标记、入场/结算日期与价格、股票收益、基准收益、超额收益和状态。结果永久增量保存，可通过版本字段重算。

### 增量计算

新增独立 `OpportunityCalibrationService`：读取尚未完成的历史快照，按股票批量加载从最早待验证日期到当前日期的 OHLC 数据，并按交易日索引计算成熟结果。股票和对应基准数据各批次只加载一次，避免逐样本网络请求。

每日机会刷新完成后，在同一个后台任务尾部执行校准；手动刷新也会触发。单只股票或基准加载失败只记录该样本错误，不影响其他股票，也不覆盖已有成功结果。

### API

新增只读接口：

- `GET /opportunities/calibration?scope=top3|all`
- 返回 5/20/60 日统计、待验证数量、最近计算时间和数据状态。

默认 `scope=top3`，因为它对应总览实际优先展示的核心排序；用户可以切换“前三名/全部机会”。

### 前端

在“今日机会”下方增加默认折叠的“机会质量”区域。每个周期显示：已验证样本数、胜率、跑赢率、平均收益、平均超额收益和最大亏损。样本不足时明确显示“样本积累中”，不渲染误导性的百分比。

## 测试与验收

- 单元测试覆盖下一个交易日开盘入场、5/20/60 交易日结算、基准日期对齐、价格缺失、未成熟样本及重复运行幂等。
- 存储测试覆盖唯一键、成功结果不可被失败覆盖、前三名和全部样本聚合。
- API 测试覆盖两个 scope、非法参数和空样本。
- 前端测试覆盖默认折叠、scope 切换、样本不足和完整指标。
- 手工验收确认页面口径文案、移动端布局及后台重复刷新不会重复计算成熟结果。

## 非目标

- 第一版不做统计显著性检验、行业中性化、交易成本或组合资金曲线。
- 第一版不把校准结果反向自动调整评分权重；先积累足够样本，再决定是否校准模型。
