# 重大历史事件设计规格

## 目标

在总览页港股和美股自选股的价格走势图中增加“重大历史事件”视图。用户可在当前价格区间内识别异常上涨或下跌，点击图表标记后立即查看有证据支持的事件归因，并通过原文链接进一步核查。

该功能只用于历史研究，不把新闻相关性表述为已证明的因果关系。证据不足时必须显示“原因未确认”，不得由模型强行补全原因。

## 范围

- 支持港股和美股自选股。
- A 股不显示“重大历史事件”Tab，也不执行分析。
- 分析范围跟随图表当前选择的 `1Y`、`3Y`、`5Y` 或 `ALL`。
- `1D` 和 `1M` 不提供历史事件分析，避免在过短区间内产生低价值结果。
- 第一版聚焦大涨、大跌事件，不提供任意日期的自由调查；后续可增加“查看该日期附近事件”。

## 重大波动定义

个股满足以下任一固定阈值，并且该周期收益绝对值超过过去 60 个交易日同周期正常波动的 2.5 倍时，记为候选重大波动：

| 周期 | 港股/美股个股 | ETF/指数 |
| --- | ---: | ---: |
| 1 个交易日 | 8% | 4% |
| 3 个交易日 | 15% | 7% |
| 5 个交易日 | 20% | 10% |

- 收益率使用复权收盘价计算。
- “正常波动”使用触发日之前、且不包含当前事件的最近 60 个同周期收益率计算标准差；少于 40 个有效样本时只使用固定阈值，并标记波动过滤不可用。
- 上涨和下跌使用对称阈值。
- 相邻 5 个交易日内、方向相同的重叠窗口合并为同一个事件波段；方向相反的剧烈波动保留为独立事件。
- 合并后的事件保留最大绝对累计涨跌幅、对应起止日期和所有触发周期。
- 事件按最终方向标记为“大涨事件”或“大跌事件”。

## 归因规则

每个候选事件检索事件开始前 3 个自然日至事件结束后 2 个自然日的证据。证据优先级为：

1. 公司公告、交易所和监管披露。
2. 财报、业绩预告和投资者关系材料。
3. 可信财经媒体的直接报道。
4. 行业、政策和宏观市场新闻。

AI 只负责从已有证据中归纳，不自行创造事实。最终归因包括：

- `driver_type`：财报、公司公告、监管政策、行业事件、宏观市场或原因未确认。
- `primary_driver`：一句话主要驱动因素。
- `narrative`：2–4 句事件过程与市场反应。
- `confidence`：高、中、低。
- `evidence`：标题、发布日期、来源、URL 和证据类型。
- `alternative_factors`：有明确证据时才列出次要因素。
- `causality_note`：固定披露“新闻与价格波动的时间相关性不等于已证明的因果关系”。

没有足够可靠证据时，`driver_type` 和主要结论均为“原因未确认”，可以列出同期相关信息，但不能使用确定性措辞。

## 市场对照

- 港股使用恒生指数作为默认基准。
- 美股使用标普 500 作为默认基准。
- 记录事件期间股票收益、基准收益和相对收益。
- 股票与基准的绝对收益差达到 5 个百分点，且存在公司级证据时，标记为“个股事件驱动”。股票与基准同方向、收益差小于 5 个百分点且存在市场级证据时，标记为“市场整体驱动”。其他情况不做确定分类。

市场对照是归因证据之一，不改变重大波动检测阈值。

## 用户界面

### 入口与加载

- 在价格图的“价格 / 市盈率 / 市净率 / 市值”控制旁增加“重大历史事件”Tab。
- 仅港股和美股显示该 Tab。
- 用户首次点击后才检测和归因，不随总览页加载自动计算。
- 已有缓存时立即显示；首次分析显示阶段进度和可读错误。
- 当前区间切换后，只加载该区间内事件，并只补算缓存缺失的事件。

### 图表

- 保留价格走势图。
- 大涨事件使用红色向上三角，大跌事件使用绿色向下三角。
- 事件持续区间使用浅色阴影。
- 标记显示事件日期和累计涨跌幅。
- 图表上方显示事件总数、大涨数量和大跌数量。

### 点击事件标记

点击三角后直接在图表附近打开摘要浮层，包含：

- 事件日期和累计涨跌幅。
- 主要驱动因素。
- 驱动类型和置信度。
- 同期基准涨跌。
- 最多 3 条关键证据及原文链接。
- “查看完整分析”按钮。

点击“查看完整分析”后展开图表下方对应的完整事件报告。点击关闭按钮或图表空白处收起浮层。大涨和大跌使用相同交互。

### 完整事件列表

- 位于图表下方，按时间倒序排列。
- 默认折叠，一次只展开一个事件。
- 展示主要驱动、发生过程、市场对照、关键证据、其他可能因素和可靠性说明。
- 原因未确认的事件仍保留价格事实、市场对照和已检索证据。

## 本地缓存

- 后端本地保存，不使用浏览器 `localStorage` 作为唯一数据源。
- 事件缓存键为 `symbol + event_start + event_end + detector_version + analysis_version`。
- 价格区间不是缓存键；同一事件在不同图表区间复用。
- 缓存永久保留，正常加载不重复调用 AI。
- 提供单只股票“重新分析”按钮；默认只补算缺失事件，显式重新分析才使用当前分析版本更新归因。
- 算法版本升级时保留旧结果，并生成新版记录。

建议每个事件保存结构化 JSON、归因报告 Markdown、原始证据 JSON 和处理日志；使用 SQLite 索引股票、日期、方向和版本，便于按当前区间查询。

## API 边界

- 创建或补充某股票当前区间的历史事件分析任务。
- 查询任务状态和阶段进度。
- 按股票与日期区间读取事件列表。
- 读取单个事件完整报告。
- 显式重新分析单只股票。

分析任务在后台执行，不能阻塞其他行情和机会接口。并发请求必须复用同一任务，避免重复计算。

## 错误与降级

- 行情不足：说明无法计算对应区间，不创建空归因。
- 新闻源不可用：保存价格事件并标记归因待补充。
- AI 不可用：仍展示价格、阈值、市场对照和原始证据，归因显示原因未确认。
- 单个事件失败：不影响同一股票其他事件结果。
- API 返回结构化错误，前端不得显示 `[object Object]`。

## 测试与验收

- 验证 1/3/5 日阈值、60 日波动过滤和涨跌方向。
- 验证重叠窗口只生成一个事件。
- 验证复权价格计算，不因拆股或分红制造虚假事件。
- 验证港股、美股可用，A 股不显示入口。
- 验证区间切换只展示范围内事件。
- 验证点击三角立即显示正确摘要，完整分析可展开。
- 验证没有证据时显示原因未确认。
- 验证缓存命中不重复抓取新闻或调用 AI。
- 验证刷新页面后历史事件仍存在。
- 验证公司公告与新闻原文链接可追溯。

## 后续范围

第一版完成后可增加点击价格曲线任意日期并调查前后 5 个交易日的功能。该功能与重大事件检测分离，不纳入第一版。
